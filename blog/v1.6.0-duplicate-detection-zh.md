# v1.6.0：重复检测 + 5倍性能提升 — AI 记忆管理器又进化了

我们刚刚发布了 [Knowledge Keeper MCP v1.6.0](https://github.com/zsc-glitch/knowledge-keeper-mcp)，带来了两个重要改进：全新的重复检测工具，以及分析/导出/同步操作 2-5 倍的性能提升。

## 🆕 新功能：`knowledge_duplicates`

知识库越用越大，重复内容就悄悄溜进来了——同一个概念保存了两次，措辞略有不同；一条决策和已有的重叠……时间长了，知识库变得臃肿。

新的 `knowledge_duplicates` 工具帮你自动找出这些问题：

```
knowledge_duplicates(threshold=0.7, scope="both")
```

**工作原理：**
- 基于词集的 Jaccard 相似度计算
- 标题权重 60%，内容权重 40%（可配置只检测标题/内容）
- 阈值可调（0.1-1.0，默认 0.7）
- 返回相似组 + 合并建议

**输出示例：**
```
1. 🔗 相似度 0.85（2 个）
    - [concept] React Server Components (2026-04-10)
    - [concept] React Server Components (2026-04-15)
    💡 建议保留较新的条目，合并另一个
```

一条命令找重复，一条命令合并。知识库干干净净，搜索结果更精准。

## 🚀 性能优化：2-5 倍提速

v1.5.0 消除了一个隐蔽的反模式：8 个文件中 14 处代码调用 `searchKnowledge({ query: "" })`，仅仅是为了"获取所有条目"。这意味着每次分析、导出、同步操作都要走完整个搜索流程（加载→过滤→排序），而我们只需要原始数据。

**修复方案**：一个 `loadAllEntries()` 函数，直接读取 `index.json`。不过滤、不排序、不走搜索。

**最严重的案例**：云同步在循环内部调用——每同步一个远程项就读一次索引。50 个条目 = 50 次完整索引加载。我们把读取提到循环外面：**1 次读取代替 50 次**。

v1.5.1 进一步把 6 个重复的 `loadAllEntries()` 实现合并到 `core.ts` 的一个公共导出，删掉了 263 行重复代码。
